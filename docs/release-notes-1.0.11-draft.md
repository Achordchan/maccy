# Klip 1.0.11 发布说明（草案）

> 草案：随开发更新，发布前再整理成用户看的版本。manifest 里的 `notes` 字段要用短版本。

## 这个版本是什么

客户端用 Go 和 MyGo 重写，单个程序，不再需要 .NET 运行时。目标是更小、更省内存，并且能在 macOS、Linux 上运行。**从 1.0.10 及更早版本升级后，历史记录、设置、登录状态和云端同步都保持原样。**

## 云同步：行为说明

这几条是现有行为，不是新问题，但值得在发布说明里写明，免得用户误会。

1. **两台设备都改了，较新的一次捕获会覆盖对方的改动。**
   设备 A 和设备 B 都在上次同步之后改了历史时，客户端比较两边最新一条记录的捕获时间（相差 2 秒以内视为没有变化）：本地更新就上传并覆盖云端，云端更新就下载并覆盖本地。**不会合并**，被覆盖那一边在两次同步之间新增的条目会丢失。
   只有“这台设备第一次同步，而本地和云端都有数据”时才会合并（合并前会把本地历史备份到 `sync/backups/pre-merge-*.sqlite`）。
   建议用法：同一时间只在一台设备上整理历史；改动后等“同步成功”再去另一台设备。
   （1.0.10 就是这个规则，1.0.11 保持一致，没有改。如果以后要改成总是合并，需要单独做决定。）

2. **新账号第一次同步现在会自动上传。** 1.0.10 在云端还没有快照时报“云端还没有快照”，要手动点“上传”；1.0.11 会直接把本地历史传上去。

3. **同一张图片在 1.0.10 和 1.0.11 上被识别为重复的情况会少一些。** 图片的去重依据是保存下来的 PNG 文件的哈希，两个版本编码出来的 PNG 字节不完全相同，所以同一张截图在两个版本上各捕获一次，会当成两条。文本和文件列表的哈希与 1.0.10 完全一致。

## 升级与兼容

- Windows：数据目录仍是 `%LOCALAPPDATA%\maccy`，程序文件名仍是 `maccy.exe`（旧版本的自动更新要求这个名字），设置、历史、图片、文件缓存和同步状态原样沿用。
- 旧版本的自动更新会下载 1.0.11 的 zip 并覆盖安装目录；原来的 .NET 文件会留在目录里，不影响运行，后续版本再清理。
- 云同步协议不变：1.0.10 和 1.0.11 的设备可以同时用同一个账号。同步快照的格式没有改。
- 安装包继续用同一个应用 ID，覆盖安装不会出现第二份。

## 不再支持

- **32 位 Windows**（`win-x86`）。SQLite 组件只有 64 位版本。
- 随安装包多了一个 SQLite 动态库（Windows 是 `mygo-sqlite3.dll`，约 1.4MB）。

## 已知限制（1.0.11 首发）

- “鼠标晃动呼出 Shelf”只在 Windows 上有。
- macOS / Linux 上没有“来源应用”信息（`SourceAppName` 为空）。
- Linux 的托盘需要 `libayatana-appindicator3`。
